# 下一阶段三方向实验计划（预注册）

计划制定于 2026-07-30，当前状态为**方案已确认、尚未开始数据整理和训练**。本计划承接 Qwen3.5-27B 与 Qwen3.6-27B 多模态 LoRA 阶段，目标是在不继续宽泛扫参的前提下，从数据、任务架构和现有 Qwen 训练方式三个方向提高图片级 GOOD/BAD 判断能力。

## 1. 当前依据与总体判断

- Qwen3.6 E1～E5 均显著超过自身未微调 Base，但 Dev 选出的 E5-780 在复核 Test N=241 上只有 Recall 69.70%、FPR 22.86%、Accuracy 75.10%、F1 60.53%，未达到 Recall≥72% 的 Go 门槛，且四项业务指标均未超过 Qwen3.5 E5-780 的历史对照。
- 所有正式 LoRA 的严格 JSON 合法率已达到 100%，当前主要瓶颈是视觉判别和跨分布泛化，不是输出格式。
- E3 表明扩大 ViT LoRA 范围没有正向收益；E4/E5 表明增加同源 crop 和重复训练行主要改变 Recall/FPR 权衡，没有替代新增独立图片。
- 当前 Dev 只有 58 个 BAD，复核 Test 只有 66 个 BAD，少量百分点差异的统计稳定性不足。继续调参前必须扩大开发评测样本，并建立新的未观察盲测集。

因此下一阶段固定为三个方向：

1. 新增独立 GOOD/BAD 数据并重建开发、盲测体系；
2. 训练专用视觉二分类器，验证“分类器初筛 + Qwen 解释/复核”；
3. 基于 Qwen3.5 验证高视觉分辨率和 decision-only 多任务监督。

暂不把更换另一种大型 VLM 基模列入前三优先级。只有本计划三个方向均无法带来稳定收益时，才启动 Qwen3-VL、InternVL3.5 或 GLM-V 等基模横评。

## 2. 统一实验边界

- 核心任务始终是图片级 GOOD/BAD；`categories`、`reasons`、bbox/crop 仅为辅助信息。
- 当前复核 Test N=241 不再用于 checkpoint、阈值、Prompt、数据配比或训练参数选择。
- 新盲测 Test 在候选模型、阈值和推理协议全部冻结后只运行一次；Test 结果不得触发同批次改选。
- Qwen3.5/Qwen3.6 已验证环境和资产保持不变。新模型、新依赖必须使用新的隔离环境。
- 所有实验保存数据 manifest、SHA256、模型版本、环境版本、随机种子、训练日志、checkpoint、原始预测和严格评测结果。
- 数据按来源组切分，不按单张图片随机切分；近重复、同一生成任务、同一主体系列和派生图片不得跨 Train/Dev/Test。
- 主要指标为 TP/FN/FP/TN、Recall、FPR、Accuracy、Precision、F1；有连续分数的模型额外报告 ROC-AUC、PR-AUC、Brier Score、可靠性曲线和风险—覆盖率曲线。
- 关键对比使用逐图配对结果、bootstrap 置信区间和 McNemar 检验；不只比较四舍五入后的汇总百分点。

## 3. 方向一：新增数据与评测体系

### 3.1 第一阶段数量

第一阶段新增 12,000 张独立图片，不包含现有约 8,026 张 Train 原图：

| 用途 | GOOD | BAD | 合计 |
|---|---:|---:|---:|
| Train | 4,000 | 4,000 | 8,000 |
| 扩展 Dev | 1,000 | 1,000 | 2,000 |
| 新盲测 Test | 1,400 | 600 | 2,000 |
| **总计** | **6,400** | **5,600** | **12,000** |

Train 采用类别平衡以充分学习 BAD 边界；新 Test 保留更多 GOOD，以提高 FPR 估计精度并接近当前业务数据结构。Dev/Test 的 GOOD/BAD 数量均固定，不通过后续模型结果调整。

### 3.2 数据准入与审计

正式划分前先从候选池随机抽取 400 张（GOOD/BAD 各 200）进行二次人工复核，统计标签一致率、争议率和反转率。若任一类别反转率超过 5%，先统一标注标准并重新抽检，不直接进入训练。

每张图片至少记录：

- 唯一 `image_id`、绝对路径和文件 SHA256；
- `decision`（GOOD/BAD）；
- 原始来源目录或批次；
- 可获得时记录生成器、生成时间、prompt/任务 ID、主体系列和人工筛选批次；
- `group_id`，用于约束同源图片不跨集合。

数据审计包括文件可读性、分辨率/宽高比、精确哈希、感知哈希或视觉 embedding 近重复、现有 Train/Dev/Test 重叠、来源分布和标签分布。裁剪、压缩副本、缩放副本不能计为新增独立图片。

### 3.3 嵌套训练子集

新增 Train 构造为严格嵌套集合：

| 子集 | 新增 GOOD | 新增 BAD | 新增合计 |
|---|---:|---:|---:|
| D2K | 1,000 | 1,000 | 2,000 |
| D4K | 2,000 | 2,000 | 4,000 |
| D8K | 4,000 | 4,000 | 8,000 |

`D2K ⊂ D4K ⊂ D8K`。固定模型配置分别训练，形成数据学习曲线。如果 D2K→D4K→D8K 持续提升，则继续扩充数据；如果 D4K 后饱和，则优先检查模型、分辨率和监督目标；如果数据增加导致退化，则暂停扩充并复核标签与来源偏差。

### 3.4 方向一交付物

- 只读原始候选池清单；
- 去重与重叠审计报告；
- Train D2K/D4K/D8K、扩展 Dev、新盲测 Test 的冻结 manifest 和哈希；
- 人工复核抽检记录；
- 各集合按来源、标签、分辨率和批次的统计报告。

## 4. 方向二：专用视觉二分类器

### 4.1 第一候选与系统定位

第一候选固定为 **SigLIP2 So400m NaFlex + 二分类头**。第一轮不同时引入 DINOv3/ConvNeXt；只有 SigLIP2 路线触发停止条件后，才讨论第二视觉骨干。

系统目标为：

```text
图片 → 视觉分类器
          ├─ 高置信度 GOOD：直接输出 GOOD
          ├─ 高置信度 BAD：交给 Qwen 生成 categories/reasons
          └─ 低置信度 REVIEW：交给 Qwen 或人工复核
```

分类器负责稳定、可校准的 GOOD/BAD 概率；Qwen3.5 负责解释和复杂语义复核。第一阶段只验证分类器本身，不立即实现生产级路由。

### 4.2 数据与学习曲线

- 只使用完整原图，不使用现有 crop 派生行。
- C0：现有约 8,026 张独立 Train 原图。
- C2K/C4K/C8K：分别在 C0 上加入 D2K/D4K/D8K。
- 扩展 Dev 2,000 张作为主要模型和阈值选择集；旧修正 Dev 200 张只用于历史连续性对照。
- 新盲测 Test 不参与 C0/C2K/C4K/C8K 选择。

### 4.3 两档训练

1. **线性探针**：冻结 SigLIP2，仅训练二分类头，判断预训练视觉特征是否已包含异常信息。
2. **部分解冻**：仅在线性探针达到最低可用水平后，解冻视觉编码器顶部若干层；分类头和编码器使用不同学习率。

第一轮使用 NaFlex 原生宽高比输入，预检 `max_num_patches=1024` 的显存和吞吐后将其固定，不与学习曲线同时做分辨率扫参。只有部分解冻仍稳定提升，才考虑全量微调。

### 4.4 阈值与选择规则

在扩展 Dev 上固定两个工作点：

- **平衡型工作点**：限定 FPR≤10%，在合格阈值中按 Recall、Accuracy、F1 降序选择；
- **召回型工作点**：限定 FPR≤20%，在合格阈值中按 Recall、Accuracy、F1 降序选择。

阈值必须在扩展 Dev 冻结，不允许在新 Test 单独重调。最终同时报告自动放行、自动拦截和 REVIEW 比例。

### 4.5 继续与停止条件

满足任一条件即可继续两阶段融合研究：

- 在相同 FPR 下，Recall 明显高于固定 Qwen3.5 对照；
- 在相同 Recall 下，FP 明显减少；
- 单模型指标未超过 Qwen，但逐图错误与 Qwen 明显互补，融合后净错误减少；
- C2K→C4K→C8K 呈稳定正向学习曲线。

若线性探针和部分解冻均明显弱于 Qwen，且新增数据没有稳定收益，则停止 SigLIP2 路线，不进入全量微调和生产路由开发。

## 5. 方向三：Qwen3.5 视觉输入与监督目标改造

### 5.1 固定基线

- 基座使用当前表现更可靠的 Qwen3.5-27B，不继续以 Qwen3.6 作为本方向首轮基座。
- 继续使用 LLM+aligner `all-linear` LoRA，冻结 ViT；rank 16、alpha 32、dropout 0.05。
- BF16、FlashAttention 2、DeepSpeed ZeRO-2、全局 batch 16、固定随机种子。
- 不增加 crop 比例，不提高 LoRA rank，不全量解冻 ViT。
- 每 0.25 epoch 保存 checkpoint，训练上限 2 epoch；按图片级 Dev 指标选择，不按 `eval_loss` 单独选择。

### 5.2 Q1：高视觉分辨率

唯一变量为：

- 基线 `IMAGE_MAX_TOKEN_NUM=1024`；
- Q1 `IMAGE_MAX_TOKEN_NUM=1536`。

Q1 继续使用现有 broad-clean 单图数据和完整 JSON Prompt，不加入新增标签数据，不修改 loss、学习率和 LoRA 范围。正式训练前重新统计全量 token 长度、截断率和显存；如 1536 无明确收益，不继续测试 2048。

### 5.3 Q2：decision-only 多任务监督

Q2 固定 `IMAGE_MAX_TOKEN_NUM=1024`，唯一实质变化是加入新增 D8K 标签数据。新增数据不伪造 categories/reasons，而是使用独立二分类 Prompt：

```text
判断图片是否存在明显的 AIGC 生成异常。只输出 GOOD 或 BAD。
```

现有带原因数据继续使用完整 JSON Prompt。由此形成两个任务：

| 任务 | 数据 | 输出 |
|---|---|---|
| 二分类任务 | 新增 D8K | 单个 GOOD/BAD 标签 |
| 解释任务 | 现有高质量数据 | decision + categories + reasons 严格 JSON |

正式推理仍使用解释任务 Prompt。第一版通过不同 Prompt 的混合多任务实现，不修改 ms-swift token loss；不把模型生成的伪原因当作人工真值。

### 5.4 Q3：组合实验

只有 Q1 和 Q2 在扩展 Dev 上都得到独立正向结果，才运行 Q3：

- D8K decision-only + 现有解释任务；
- `IMAGE_MAX_TOKEN_NUM=1536`；
- 其余配置沿用固定基线。

如果 Q1/Q2 只有一个方向有效，则直接保留有效方向，不为了完整性强行运行组合实验。

### 5.5 后续参数实验边界

学习率首轮沿用既有 `5e-5`。只有 Q1/Q2 出现明确的早期过拟合，才单独比较 `5e-5` 与 `2e-5`；不得同时修改学习率、分辨率和数据任务。当前阶段不安排 rank、alpha、dropout、ViT 范围和 crop 比例的网格搜索。

## 6. 跨方向执行顺序

### 阶段 A：数据冻结

完成 12,000 张数据的抽检、去重、分组划分、manifest 和哈希。此阶段不训练模型。

### 阶段 B：固定对照重评

在扩展 Dev 上评测并冻结当前 Qwen3.5 最佳平衡模型、召回模型以及 Qwen3.6 E5-780，生成逐图基线。该评测只用于后续配对比较，不改动旧模型。

### 阶段 C：低成本分类器实验

依次运行 SigLIP2 线性探针 C0/C2K/C4K/C8K；确认学习曲线后，只对最有价值的数据规模运行部分解冻实验。

### 阶段 D：Qwen 受控实验

分别运行 Q1 和 Q2；按预注册规则判断是否需要 Q3。三个实验使用独立输出目录和完全相同的扩展 Dev 评测协议。

### 阶段 E：系统候选选择

在扩展 Dev 上比较：

- 固定 Qwen3.5 对照；
- 最佳 SigLIP2 单模型及两阶段候选；
- 最佳 Qwen Q1/Q2/Q3 候选。

平衡型和召回型工作点分别选择，不混为一个排序。除汇总指标外，必须检查异常类型、来源、分辨率和置信度切片。

### 阶段 F：一次性新盲测

候选、阈值、Prompt 和协议全部锁定后，运行新 Test 2,000 张。固定 Qwen3.5 对照可与最终候选同时评测，用于配对比较；不得根据 Test 结果回到同批计划改选。

## 7. 阶段成功标准

本阶段至少需要实现以下一种可验证收益：

1. 平衡型工作点在 FPR≤10% 下，Recall 和配对净正确数显著超过当前 Qwen3.5 对照；
2. 召回型工作点在 FPR≤20% 下达到更高 Recall，且 Accuracy/F1 没有不可接受退化；
3. 两阶段系统在可接受 REVIEW 比例下形成更优的质量—成本 Pareto；
4. 数据学习曲线证明继续增加独立标签数据具有稳定边际收益。

若新盲测未确认 Dev 收益，结论记为泛化失败，不使用当前 N=241 Test 或其他 checkpoint 补救；后续重新立项并使用新数据批次验证。

## 8. 明确不做的事项

- 不将当前 Dev/Test 错误样本直接回流新增 Train；
- 不用 Qwen 自动生成原因并当作人工标注真值；
- 不把裁剪、压缩、缩放和近重复副本计为新增图片；
- 不复用 Qwen3.5/Qwen3.6 trainer state、优化器或 token 缓存；
- 不破坏现有 `qwen35_27b`、`qwen36_27b` 和已验证部署环境；
- 不在同一实验同时修改数据、分辨率、学习率、LoRA rank 和视觉解冻范围；
- 不因公开通用榜单成绩直接投入另一大型 VLM 的完整 LoRA 训练。

## 9. 当前下一步

下一步只推进阶段 A：确认新增数据的实际组织形式和可用元信息，随后编写只读盘点、去重和分组划分方案。在数据 manifest 与拆分规则确认前，不启动 SigLIP2 或 Qwen 训练。
